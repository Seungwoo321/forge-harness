# Codex 관리 작업자의 기동 전 훅 신뢰 결속

## 문맥

Codex 관리 작업자의 시작 영수증은 별도 app-server의 `hooks/list` 관찰로 Stop 훅 강제를 검증했다. 이 관찰은 관찰 시점의 account/cwd 설정만 증명한다. 이미 실행 중인 작업자가 어떤 훅 내용을 적용했는지는 증명하지 않는다. 승인 전에 기동한 작업자나 기동 뒤 플러그인 내용이 바뀐 작업자는 영수증과 다른 훅 상태로 실행될 수 있다.

시작 intent는 `executeEffect`가 실행 전에 원장에 기록한다. 실행 안에서 거부하면 수신자 없는 불확실 intent가 남는다.

## 결정

1. 관리 Codex 작업자는 필수 플러그인 훅(SessionStart, Stop)이 trusted 또는 managed로 관측된 뒤에만 기동한다.
2. 세션 어댑터는 `preflight({effect,args})`를 제공한다. 같은 account·cwd의 `hooks/list`를 읽기 전용으로 관찰하고, 필수 훅이 enabled·동기·trusted/managed가 아니면 원인(trustStatus 등)을 담은 `SESSION_HOOK_UNTRUSTED` 오류로 거부한다. 거부는 intent 기록 전에 일어난다. 훅 승인은 자동으로 하지 않는다.
3. 사전 관찰한 훅의 event·key·hash를 시작 intent 인자 `enforcement`에 결속한다. effect key는 바뀌지 않는다.
4. 시작 검증은 현재 관찰한 필수 훅이 trusted이고 key·hash가 intent에 결속된 값과 같을 때만 강제를 인정한다. 다르면 미검증과 원인을 보고한다.
5. 사전 관찰이 없는 기존 시작 intent는 미검증이다. 기동 시점의 신뢰는 사후에 증명할 수 없기 때문이다.
6. 공개 복구가 예약하는 다음 attempt는 원 attempt의 결속을 승계하지 않고 기동 전에 다시 관찰한다.
7. 훅 상태를 관찰하지 않는 작업자(Claude)는 사전 관찰을 하지 않으며 기존 동작을 유지한다.

## 기존 시작의 복구

사전 관찰 없이 기동한 시작은 다음 순서로 다룬다. 공식 배포본의 내용을 확인한다. 관찰된 그 hash만 호스트의 네이티브 설정으로 승인한다. 같은 공개 시작을 다시 호출해 같은 intent를 재조정한다. 재조정은 재기동·재제출·영수증 기록 없이 같은 수신자를 재관찰하며, 결속이 없으므로 원인과 함께 미검증으로 남는다. 작업을 이어야 하면 원 수신자 종료와 미착수 증명을 요구하는 기존 공개 시작 복구로 다음 attempt를 예약하고, 그 attempt는 기동 전에 훅을 관찰한다.

## 제외한 방법

- 기동 뒤 실제 Stop 훅 실행을 증명으로 요구하는 방식: 모든 첫 시작이 자연 Stop 경계까지 미검증으로 남는다.
- 실행 안에서 거부: 수신자 없는 불확실 intent를 남긴다.
- 기존 시작에 현재 관찰을 사후 결속: 기동 시점 신뢰를 위조하는 경로가 된다.
