# 정책 승인 출처의 별도 정정 기록

## 문맥

운영자가 전달한 문구가 원 사람의 승인 참조로 잘못 기록될 수 있다. 정책 값을 왕복 변경하거나 동일 요청을 새 참조로 재시도하는 일은 원 출처 오류를 정정하지 않는다.

## 결정

공개 `unit policy approval-correct`는 현재 미수용·미전달 변경 단위의 마지막 delivery 정책 변경을 원 사람의 실제 권한으로 재검증한다. 요청은 정확한 revision과 원 변경 행의 index/digest를 지정한다. 신뢰된 제공자는 요청·단위·이전 출처·원 변경 행·현재 Git 대상의 digest와 실제 사람의 같은 작업 권한을 검증한다.

제어면은 원장과 단위 잠금 아래 검증하고 현재 대상을 다시 관찰한다. 원 행과 현재 정책 값을 유지하고 `policyApprovalCorrections`에 별도 영수증을 추가한다. 영수증은 원 행, 정정 출처, 요청, 실측 대상과 각 digest를 결속한다. 같은 id/입력은 기존 결과를 반환한다.

진행 중 단계, 수용·전달·종료 상태, 미해결 효과, 변경된 원 행·정책·revision·대상 또는 검증되지 않은 권한은 거부한다. 정정은 게이트·리뷰·수용·전달 성공을 생성하거나 복원하지 않는다. 비교 기준 복구가 필요하면 호스트는 정정된 권한과 동일 대상에 한해 역사 수용의 base를 검증용으로 사용하고 정상 수용 절차를 계속한다.

## 제외한 방법

원 행의 수정·삭제와 정책 값의 왕복 변경은 승인 이력을 정정하는 방법이 아니다. 다른 scope·goal 복구 명령을 정책 승인 정정으로 사용하지 않는다.
