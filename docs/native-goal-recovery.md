# Recover an existing native goal start

A worker paused on startup trust can remain on an empty Ready composer after the original `session.start` execution returns uncertain. Resume it through the exact original public command, review unit, request, roots and adapter registration:

```sh
node <official-package>/scripts/unit.mjs unit session-start <existing-review-unit> \
  --request <original-start.json> --state-root <original-state-root> \
  --project-root <original-project-root> --adapters <original-trusted-adapters.mjs>
```

The existing native receiver and original intent/key/sequence remain authoritative. Verification never creates another workspace or worker. Do not recreate the review unit, run the effect's execute method manually, change the request or packet snapshots, type a manual goal, or edit stored records. Host trust decisions use the host's normal verified UI; this recovery does not grant hook trust or waive native enforcement requirements.

The public effect driver supplies `input.submission` to managed `session.start` adapter execution and verification. Registered session runners forward this in-process context intact. Its asynchronous `mark(binding)` appends and syncs a `submission` ledger row for the same intent before any native input; the binding contains runtime, session/incarnation, PID/executable, native thread, exact prompt/goal digest and immutable packet references. The context records recovery mode, prior binding and whether a prior completed effect makes the operation observation-only. A runner invoked outside that driver cannot manufacture this durable fence. No function is serialized into stored effect arguments and the public request schema stays unchanged.

For an unresolved legacy intent with no submission row, recovery needs positive native absence and the exact empty Ready receiver. Codex reads actual thread history and pending queue even when the native goal table has no row. Prior native work, queued input, another goal or unsupported observation remains unknown. Claude requires an actual metadata-only transcript without user/assistant/queued work for legacy recovery; an unavailable startup transcript only permits the driver's fresh-launch execution path, never a replay. Native identity and composer contents are rechecked after durable persistence, at the first input, and before the separate Return. A foreign draft, modal, Working state, changed process/thread or changed packet refuses input.

Codex 0.167.0 has a distinct first-input `unmaterialized` observation. Its [rollout recorder](https://github.com/openai/codex/blob/086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a/codex-rs/rollout/src/recorder.rs#L900) defers file creation, and a separate observer cannot read the owning TUI manager's fresh thread. Exact version/account and structured thread-not-loaded/no-rollout responses select this contract; those errors alone never mean empty history. The actual worker's open `queue_1.sqlite` establishes its configured SQLite root. Successful read-only supported-schema queue and goal queries for the exact thread establish no durable queue or goal. Missing/inaccessible stores or mismatching errors remain unknown; no empty history arrays or synthetic thread metadata are returned.

This first-input path additionally requires the original managed launch's immutable no-initial-input provenance, the same measured worker/thread/incarnation, an unsubmitted original intent, and a full cmux scrollback capture with the pinned native welcome and current empty Ready composer. Prior submitted-user prompts, pending-input previews, startup, approvals or ambiguous views refuse input. The native proof and current UI are rechecked after owner probes immediately before the first input and Return. Unsupported runtimes/versions use ordinary observation; they cannot substitute a missing-history fallback. The platform basis and boundaries are recorded in [ADR 0019](adr/0019-observe-unmaterialized-native-thread.md).

Once a submission row exists, recovery never blindly retypes input. A completed effect remains observation-only. If persistence succeeds and the process exits before input, absence of a receipt does not authorize another attempt. Preserve the original reviewer/intent rather than relaunching or deleting history.

The same marked intent has one narrow pending-draft continuation: its engine verification records `native goal composer did not settle`, which identifies failure before Return, and no `confirmation` row exists. Recovery requires the original complete native/prompt/packet binding, positive pinned no-goal/no-queue observation and a current full exact Ready draft. An exact pending draft proceeds without retyping. A clipped suffix or foreign text cannot authorize Return. A separate `confirmation` row is appended and synced before Enter; its presence makes all retries observation-only even after a lost Return response, cleared goal or delayed history.

Codex 0.167.0 can consume `/` as a slash-popup key while its first argument burst is still buffered. The composer waits for a short first argument to appear outside the command token before sending the remainder. A prior marked intent with the pre-Return failure can identify only the full single-line variant that lost slash characters from the original first128-codepoint burst (including its separator). This variant is a correction candidate, never an exact draft. With verified default effective project/account keymap and Vim disabled, the engine syncs a `draft-repair` row bound to the original submission plus old/new draft digests, rechecks native owner/absence/full damaged text before each logical-line edit key, verifies empty, then types the full original through the fixed composer. Custom/unknown keys refuse correction. An uncertain correction is never repeated; only a fully exact completed draft can proceed through an unmarked Return. See [ADR 0020](adr/0020-recover-pending-native-draft.md).

An exact existing active/completed goal is reconciled only after native history establishes actual work start and all immutable packet reads. Managed hook enforcement and reviewer independence remain required. Successful reconciliation appends the real result to the original ledger sequence and registers that same reviewer through the normal goal custody path. Ordinary result delivery and exact managed-worker closure keep their existing contracts.
