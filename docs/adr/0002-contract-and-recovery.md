# ADR 0002: 상태·계약·권한·증거 경계의 완결성

날짜: 2026-10-28 · 대상: `docs/spec.md`

## 배경

2차 설계 검토의 27건에서 상태 전이와 데이터 계약의 누락, 전달 실패·환경 복구·동시 갱신의 잘못된 귀결을 확인했다. 이 결정은 ADR 0001의 head·커버리지·실패 서명·외부 절차 의존에 관한 결정을 대체한다.

## 결정

| 주제 | 결정과 이유 |
|---|---|
| 상태 | 전달 실행을 Delivering으로 분리한다. 모든 활동 상태에 Blocked·Stopped와 정확한 복귀 상태를 둔다. design에도 정책 리뷰를 적용한다. ops는 읽기만 허용한다. |
| 수용 | review에 ship/fix·reviewedHead를 요구한다. must-fix+ship은 거부한다. should-fix만 있으면 리뷰어가 판정한다. 게이트·AC 커버리지는 리뷰 유무와 무관하게 필수다. |
| head | 단위 브랜치 tip SHA와 검증 내용 fingerprint를 고정한다. 전달 commit은 검증된 트리와 같을 때만 SHA를 결속한다. target merge SHA는 별도로 기록한다. |
| 복구 | 환경·하네스·사용자 영역·불명 실패는 비결정 비교에서 제외한다. 실패 지점·요지 키의 예산은 재분류로 초기화하지 않는다. R 상한을 제어면 예약으로 강제한다. |
| 저장 | 공통 Git 디렉터리 아래 전용 상태·정책 루트를 두고 모든 worktree에서 공유한다. 잠금 안에서 읽기·수정·원자 교체하며 공유 큐·예약도 직렬화한다. |
| 권한 | effect 등록표가 등급·멱등 키·검증기를 소유하고 제어면이 수행한다. prelaunch의 E1 범위는 제품 소유 경로 전체다. delivery 상한은 별도로 유지한다. |
| 증거 | 테스트별 성공 보고의 이름에서만 AC ID를 추출한다. skip·todo·실패·주석은 커버하지 않는다. 비테스트 기준은 성공한 검증 결과로 연결한다. |
| 투영 | tracker null을 허용한다. 동기화 실패는 큐로 남기며 선택 tracker가 있으면 Closed 직전에만 최종 반영을 요구한다. |
| 계약 | stage 이름·reads 운반·초기값·실패 시점·riskAssessment 하위 계약을 명시한다. |
| 범용성 | provider 질문·설정·세션, clock·id는 어댑터다. 개인 절차에 의존하지 않고 결정 로직은 scripts/가 소유한다. |
| 외부 절차 | 플러그인의 정본은 이 저장소 스펙이다. 외부 개인 규칙·스킬을 수정하거나 같은 정책 파일을 공유하지 않는다. 구형 정책은 명시 매핑만 허용한다. 지원하지 않는 실행 계약은 시작 전에 거부한다. |
| 선택 | 제품 의미·UX·가격·위험에 영향 없는 기술적 동등안은 최소 변경으로 정한다. 실제 선호 차이는 사용자에게 묻는다. 더 엄격한 외부 제한은 유지하고 충돌을 알린다. |
| 프리셋 | 모든 유형에서 delivery none, isolation worktree다. 자원 권한은 전달 위임을 대신하지 않는다. |

## 외부 절차 호환성

복구 참조 문서를 포함한 실행 계약은 fix-forward·5종 실패 분류·R 상한·E0 전용 ops·정책 리뷰를 준수해야 한다. 상한 해제를 요구하거나 무조건 롤백하는 외부 지시는 적용하지 않는다. 제어면이 기동 예약·상한을 소유하므로 스킬이나 참조 문서가 예산을 늘릴 수 없다. 실행기는 계약 버전·기능을 선언하며, 미지원이면 실행 전 거부한다. 외부 개인 설치의 마이그레이션은 해당 소유자의 별도 작업이며 이 저장소가 개인 설치 파일을 자동 수정하지 않는다.

## 결과

외부 개인 환경 없이 구현할 수 있다. ADR 0001의 개인 설치 경로 목록은 범용성에 맞게 제거하고 대체 결정은 이 ADR로 연결한다. 결정 이력은 ADR과 저장소 이력으로 보존한다.
