# 불변 패킷 읽기 증명의 진단과 안내

## 문맥

출력 압축기나 wrapper를 거친 패킷 읽기는 native 기록에서 알 수 없는 명령으로 분류되거나 내용이 잘린다. 같은 결과 안의 전체 내용과 hash 행이 없으면 검증기는 읽기를 증명하지 못한다. 이때 진단이 패킷 전달 전 부재와 같은 문구를 내면 이미 실행 중인 목표를 다시 제출해야 하는 것으로 오해할 수 있다.

## 결정

Codex 목표 관찰은 목표가 수락됐지만 읽기 증명이 없는 불변 패킷의 경로와 digest를 읽기 전용으로 반환한다. 목표 검증은 이 상태를 "native goal accepted; immutable packet read proof is incomplete"로 보고하고 지원되는 읽기 형태를 함께 안내한다. 지원 형태는 runtime이 파일 읽기로 인식한 bare 읽기의 정확한 전체 출력, 또는 한 성공 명령의 전체 내용과 그 파일의 `shasum -a 256 <절대 경로>` 행이다. 이 진단은 착수 영수증이 아니며 재제출을 허용하지 않는다.

검증기는 약화하지 않는다. 압축·절단된 출력, 인식되지 않은 다른 명령의 hash, digest 단독, 자기 신고는 증명이 아니다.

## 제외한 방법

목표 prompt에 안내 문구를 추가하지 않는다. 검증은 같은 인자로 prompt를 다시 구성해 원 objective와 정확히 비교하므로, 문구 변경은 버전 교체 뒤 이미 실행 중인 원 목표의 정합화를 막는다. 안내는 진단과 단위 스킬이 담당한다.
