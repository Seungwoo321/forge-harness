# Read wrapped result references from the native composer

## Context

The narrow Codex footer omits its Ready/Working segment while retaining the model, directory and shortcut hints. Result delivery duplicates a stricter screen parser and assumes that every packet reference fits one terminal row. Those assumptions reject a supported native composer before the original delivery intent can resume.

## Decision

Codex result delivery shares native goal composer extraction and expected-text matching across visual rows. The normal shortcut/queue footer remains required. Native thread readiness, queue state and process incarnation checks authorize input; an omitted display status does not establish readiness. The bounded single-line reference may wrap, but the full rendered reference must match the immutable original before Return. Only the native continuation indent is removed; extra draft whitespace is not normalized away.

The same intent and receiver remain authoritative. Verification rechecks the unchanged composer after identity checks before paste and before Return. Foreign, clipped, changed or unsettled drafts refuse submission. A native queued, accepted or started request remains observation-only and successful delivery still requires actual native activity and packet-read evidence. This changes neither closure nor hook trust contracts; account/cwd hook inventory does not prove execution by a retained worker.
