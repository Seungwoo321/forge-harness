# ADR 0006: Accepted-target delivery execution

Date: 2026-10-29 · Scope: delivery, repository adapters, verified user approvals

## Decision

The public runtime factory optionally registers `repository` and `provider` alongside existing `git`, `gates`, `tracker`, and `sessionRunner`. Git owns commit, push, and remote integration; repository owns PR creation and merge. Delivery providers expose `deliveryContext({unit,record,effect,args})`, `execute({effect,args,key,seq})`, and `verify(...)`. Required trusted context booleans identify resource ownership, product ownership, scope, operational environment, irreversibility, secret presence, and forbidden commands. Methods are required only for requested effects. Existing none integrations retain their original contract.

Acceptance snapshots repository, branch, tree, indexTree, headTree, and base from Git inspection for non-none delivery. Finish request target fields are expectations; presentation fields never override accepted identity. The Unit stores the fixed delivery plan. The control plane authorizes, checks accepted content immediately before effects, and drives the existing Unit states and append-only ledger. Commit binds a new SHA only after independent tree, index, parent, branch, and fingerprint checks. Interrupted commits reconcile before stale-head rejection. Remote integration is a registered E2 `git.integrate` operation keyed by repository, branch, head, and remoteHead, capped by push delivery. Integration requires reacceptance before outward effects.

Unknown outcomes remain uncertain and inspection-only. Definite terminal `not-applied` and `remote-ahead` outcomes require structured verification evidence. Integration may return `conflict` with observed head, tree, indexTree, and conflict paths plus verification evidence; it never implies no mutation. Retrying a resolved nonapplied attempt requires canonical recovery authority, reauthorization, and fresh target inspection. Closed or merged PRs never satisfy a new cycle; only exact open repository/branch/head/base matches are reusable.

`provider.verifyUserInput({unit,userInputRef,effect,argsDigest,head,reason})` verifies external user authority and returns `verified:true` with the identical tuple. The control plane owns approval identity and timestamp. Full canonical argument digests and the accepted head bind stored approvals; caller flags and opaque approval IDs alone confer no authority. Irreversible context elevates authorization to E4, including class allow/deny checks. Approval recording and consuming both verify the trusted input tuple.

## Consequences

The existing Unit Record and ledger remain the only lifecycle authorities. Public none providers remain compatible. Native Git/hosting integrations are explicitly supplied through trusted providers and use the command adapter. Tests replace external effects with stub commands. No force operation or hook bypass is generated by the control plane.
