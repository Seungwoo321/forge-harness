# Exact pending goal observation across terminal backends

An uncertain original session start can retain a durable submission and an exact native goal draft while an earlier discovery observation obscures the pre-Return failure. Both supported terminal backends observe this state through the same original binding proof.

The observer rechecks the exact receiver/process/thread/account, immutable prompt and packet digests, positively unmaterialized native goal and empty queue, full exact composer contents, then stable identity and native evidence. Missing or clipped text, foreign input, changed identity/account and unavailable absence evidence fail closed. Observation itself sends no input.

A successful observation records only the existing pending-draft verification. Reconciliation retains the original intent and submission and uses the existing confirmation-before-Return protocol. It never launches a replacement or repeats a confirmed Return. The first execution failure remains preserved; a later generic observation does not replace it.

The observer also invokes the same assertNativeGoalReady guard used before native submission. Draft equality alone never establishes Ready: Working, unknown or absent footer, modal, queued or startup views cannot create a pending-draft annotation.
