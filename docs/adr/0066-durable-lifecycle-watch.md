# 영속 생명주기 관찰과 소유자 깨우기

## 문맥

Stop 훅은 Stop 이벤트가 호출될 때만 동작하고, 세션 runner의 재관찰은 호출 프로세스가 살아 있는 동안의 짧은 polling이다. 완료된 CLI 호출, 유휴 모델 턴, 재부팅 뒤에는 외부 조건 변화(CI·리뷰·전달)를 다시 관찰할 주체가 없다. 현재는 별도 설치하는 외부 스케줄러 플러그인이 이 역할을 한다. Stop 프롬프트를 늘리거나 polling을 길게 해도 영속 관찰은 생기지 않는다.

## 결정

1. 관찰(watch)은 목표·단위·현재 custody·정확한 native 수신자 신원에 결속된 정본 기록이다. 생성·일시정지·재개·제거·정합화는 공개 `unit watch …` 명령이 소유하고, 정본 쓰기는 기존 잠금 순서(원장→단위→목표)를 따른다.
2. 기계적 조건 확인(정본 상태·원격 상태)은 모델 호출 없이 실행한다. 결정이나 행동이 실제로 필요할 때만 승인된 소유자를 깨운다. 작업 중인 소유자에게는 중복 입력을 보내지 않고 기존 native queue·소유자 경계 계약만 사용한다.
3. 깨우기는 기존 효과 원장 규약을 따른다. intent와 예산을 먼저 기록하고 수신자별로 직렬화하며, 제출·transport 수락·실제 native 턴 시작·작업 결과를 구별한다. 불확실한 시도는 정합화 대상으로 남기고 맹목 재전송하지 않는다.
4. 제공자 중립 backend 계약 하나를 둔다. 필요한 생명주기 보장이 검증된 네이티브 큐에 하네스 소유 영속 runner로 전달한다. 수신자 하나에는 정확히 하나의 backend만 둔다.
5. 사용자 일시정지·실제 차단·한도·설치 HOLD는 재시작 뒤에도 유지된다. 놓친 발생은 병합하고 만료·유한 예산·잠금 복구를 정의한다. 정상 인계·종료가 끝난 뒤 그 수신자의 관찰만 제거한다. Closed 단위·바뀐 custody·만료된 관찰은 재사용된 surface를 깨우지 않는다.
6. 관찰은 게이트·독립 리뷰·사람 권한·실제 훅 집행·종료 검증을 면제하지 않는다.

## 확정된 실행 모델

Node 내장 모듈로 간격(`everyMs`) 기반 실행기를 구현한다. 외부 엔진·cron 라이브러리·별도 플러그인 설치에 의존하지 않는다.
감시 등록과 모든 감시 명령은 실행기 생존을 확인하고 필요하면 detached Node 프로세스를 자동 기동한다. SessionStart도 같은 복구를 실행한다.
실행기는 실행 가능한 감시가 없으면 스스로 종료한다. OS 서비스 등록과 사용자의 별도 데몬 기동은 요구하지 않는다.
컴퓨터가 꺼져 있거나 모든 프로세스가 강제 종료된 동안의 실행은 보장하지 않는다. 다음 SessionStart 또는 감시 명령에서 복구한다.

최초 backend는 기존 Codex `thread/queue/add`다. 정확한 수신자 신원·기존 thread·빈 composer·유휴 상태를 검증한다. 제공자 계약이 검증되지 않으면 등록을 거부한다.
조건은 모델을 호출하지 않는 명시적 명령이며 `{state, actionable}` JSON을 반환한다. 등록 때 기준 상태를 저장하고 이후 상태 변화당 한 번만 깨운다.
실행 횟수와 만료는 필수다. 네이티브 턴 시작·종료는 전송 수락과 별개로 관찰한다. 턴 종료를 목표 완료로 해석하지 않는다.

기존 외부 감시는 변경하지 않는다. 외부 저장소의 동일 네이티브 thread 또는 terminal 감시는 충돌로 거부한다.
이전은 자동 기능이 아니다. 운영자가 기존 감시를 명시적으로 종료하고 pending 영수증을 정합화한 뒤 새 감시를 등록한다.
외부 감시 정의를 새로 만들 때도 동일 수신자에 대한 중복 소유를 금지한다. 외부 도구의 직접 파일 쓰기를 원자적으로 통제할 수는 없다.
기존 외부 ID·영수증·예산·pause는 이 작업에서 수정하지 않으므로 되돌림 때 보존된다.

## 근거와 결과

Stop 훅과 호출 중 polling은 독립 시계가 아니다. 별도 설치 부담을 없애면서도 OS 등록 없이 복구하려면 배포본 소유 실행기와 SessionStart 복구가 필요하다.
알 수 없는 전송을 반복하면 동일 세션에 중복 작업이 생기므로 intent·예산을 먼저 저장하고 uncertain 시도는 관찰만 한다.
작업관리·승인·완료의 기존 정본은 바꾸지 않는다. 이 결정은 ADR 최초 제안의 외부 엔진 추출과 호스트 기동 대안을 채택하지 않는다.
